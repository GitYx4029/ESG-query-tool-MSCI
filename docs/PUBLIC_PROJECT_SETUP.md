# 公益版本：发布与反馈统计

## 网站现状

- GitHub Pages 托管公开查询、行业地图、来源核验状态和分享页面。
- 企业分析和项目管理入口经过管理员密码弹窗；所有相关直接网址也经过相同门槛。它是静态网页的界面门槛，不能替代服务器鉴权。
- 示例是代码生成的纯虚构数据，不下载或改名展示第三方企业报告。用户上传的数据不按文件名替换分数。
- 当前支持的企业分析行业：房地产管理与开发；半导体与半导体设备。
- 估算权重百分比已从公开页面移除。议题关注等级为学习参考，企业实际适用议题、分类与权重以官方资料为准。

## 已部署的轻量后端

服务地址：`https://esg-community-api.reagan-park-6434.chatgpt.site`。前端已设为默认反馈服务，也可以使用 Actions variable `VITE_COMMUNITY_API_ORIGIN` 覆盖。

- 服务运行于 Sites / Cloudflare Workers，反馈与匿名功能事件保存在 D1；无需常驻服务器，不消耗模型 token。
- `GET /api/community/health` 返回数据库可用状态。反馈必须得到 `saved: true` 才标为已保存，失败时可由用户生成邮件草稿。
- `/admin` 通过 ChatGPT 登录，只允许创建项目的所有者账号查看记录。`ADMIN_OWNER_EMAIL` 保存在托管平台，未配置或未登录时拒绝读取。
- 原网页 `4029` 只用于界面入口。每次点击“企业分析”都重新要求输入；刷新页面或离开分析区域后不恢复旧解锁状态。
- 按本轮要求移除页脚统计开关及说明，新版本停止发送匿名统计事件，也不会恢复旧标签页的同意状态。后端仍保留历史事件的90天保留和近30天汇总能力；用户反馈可以继续独立提交。
- 用户反馈单独持久化保存，联系方式只有主动填写并同意联系时才保存。后台可统一查看反馈、手工记录小红书建议、更新状态和优先级、导出最近1000条需求。
- 临时 IP 限流在 Worker 实例内运行，IP 不写入数据库；不等同于平台级防滥用。

方法学文件标题与版本核验状态及明细移至密码保护的项目管理页；公开议题地图保留原文链接。

公开网站底部“项目管理”进入后台入口。若登录后提示无权限，请确认登录的是创建项目时的账号。

仓库同时保留 Node.js 反馈服务，供未来迁移使用；它需要持久化私有磁盘、至少16字符的 `COMMUNITY_ADMIN_TOKEN` 和 `COMMUNITY_ALLOWED_ORIGINS`，不能将反馈文件放入公开静态目录。

AI 报告分析尚未接入该轻量后端。模型接口、服务端密钥与真实请求验收属于下一阶段；不要仅因反馈服务已部署就设置 `VITE_AI_API_ORIGIN`。

## 小红书入口归因

不同笔记使用不同的 `note` 值，例如：

`https://gityx4029.github.io/ESG-query-tool-MSCI/?utm_source=xiaohongshu&note=launch01`

每周查看零结果搜索比例、使用失败、受关注行业和反馈分类，将站内反馈与手工录入的小红书建议汇总在私有需求表。不要自动收集评论者联系方式。

## 验收

- 未解锁直接访问企业分析、Drilldown和项目管理网址时只显示密码入口；错误密码无法进入。
- 汽车、光伏、AI搜索能返回候选行业；未知词提供清空、返回全部行业和反馈。
- 用户Excel数值原样解析；无关Excel明确失败；示例始终标注虚构。
- 行业页和地图不出现估算权重百分比；未知版本的文件不标注已核验。
- 反馈存储失败返回失败，未鉴权不能读取记录；关闭统计后不发送事件。
- 页面至少在桌面、窄屏和小红书内置浏览器检查；真实设备和大陆网络的访问情况需单独验证。

## 界面维护原则

- 行业详情页优先呈现行业议题、相关方法学原文和简短反馈入口。
- 通用功能入口集中在顶部导航；不在每个行业底部重复添加核心方法学和企业分析卡片。
- 核验明细、运维和管理信息集中在管理员操作区，避免占用公开查询页面。
- 新增功能前先检查是否已有入口或说明，尽量减少用户完成查询的步骤和重复内容。
- 议题参考关注等级统一使用高红、中橙、低蓝、通用及未列出灰；始终保留等级文字，颜色仅作为辅助。
