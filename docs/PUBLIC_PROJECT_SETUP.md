# 公益版本：发布与反馈统计

## 网站现状

- GitHub Pages 托管公开查询、行业地图、来源核验状态和分享页面。
- 企业分析和项目管理入口经过管理员密码弹窗；所有相关直接网址也经过相同门槛。它是静态网页的界面门槛，不能替代服务器鉴权。
- 示例是代码生成的纯虚构数据，不下载或改名展示第三方企业报告。用户上传的数据不按文件名替换分数。
- 当前支持的企业分析行业：房地产管理与开发；半导体与半导体设备。
- 估算权重百分比已从公开页面移除。议题关注等级为学习参考，企业实际适用议题、分类与权重以官方资料为准。

## 接通反馈与匿名统计

GitHub Pages 本身不能接收或集中保存反馈。仓库提供一个可独立运行的 Node.js 服务，避免依赖数据库或大模型。

1. 安装依赖，运行 `npm run build:community`；部署时运行 `npm run community:start`。
2. 服务端配置 `COMMUNITY_ADMIN_TOKEN`（至少16字符的独立管理凭证）、`COMMUNITY_DATA_DIR`、`COMMUNITY_ALLOWED_ORIGINS=https://gityx4029.github.io`。页面入口密码只用于界面门槛；私有服务使用独立凭证。密钥只在托管平台的环境变量中设置。
3. `COMMUNITY_DATA_DIR` 必须指向持久化磁盘目录，并保持私有。不要放在网站静态目录或公开 GitHub 仓库。按托管环境配置数据备份、容量和保留期限。
4. 在仓库 Actions variables 设置 `VITE_COMMUNITY_API_ORIGIN=https://<反馈服务域名>`（只含公开域名，不加 API 路径），重新运行 Pages 工作流。
5. 用户选择“允许匿名使用统计”后才发送功能事件。原始搜索词、文件名、报告、评分、联系方式与密码不进入事件记录。反馈中的联系方式只在用户主动填写并同意联系时保存。
6. `GET /api/community/health` 应返回 `available: true`。访问 `/admin/insights`，通过界面密码后，输入服务端管理凭证即可查看30天汇总、手工记录小红书建议、更新优先级与处理状态、导出 CSV。

未接通服务时，网站明确显示统计尚未开启；反馈表单只生成邮件草稿，需用户自行确认发送。不能把草稿统计为已保存反馈。匿名会话数不等于真实人数；方法学链接点击不代表文件已阅读。

## 小红书入口归因

不同笔记使用不同的 `note` 值，例如：

`https://gityx4029.github.io/ESG-query-tool-MSCI/?utm_source=xiaohongshu&note=launch01`

每周查看零结果搜索比例、使用失败、受关注行业和反馈分类，将站内反馈与手工录入的小红书建议汇总在私有需求表。不要自动收集评论者联系方式。

## 验收

- 未解锁直接访问企业分析、Drilldown和项目管理网址时只显示密码入口；错误密码无法进入。
- 汽车、光伏、AI搜索能返回候选行业；未知词提供清空、返回全部行业和反馈。
- 用户Excel数值原样解析；无关Excel明确失败；示例始终标注虚构。
- 行业页和地图不出现估算权重百分比；未知版本的文件不标注已核验。
- 反馈存储失败返回失败，未鉴权不能读取记录；关闭统计后不发送事件。
- 页面至少在桌面、窄屏和小红书内置浏览器检查；真实设备和大陆网络的访问情况需单独验证。
